Cross-Site Scripting

Cross-Site Scripting (XSS) is one of the most common, and potentially devastating, vulnerabilities in web development. It occurs when untrusted input is rendered in the browser without proper sanitization or encoding, allowing attackers to inject and execute malicious scripts.

The impact can be subtle or severe: stolen tokens, session hijacking, account compromise. Often, it goes unnoticed until it is exploited. Whether you work on front-end components or backend APIs, understanding XSS is foundational. Every developer should know how it works, how to recognize the signs, and how to prevent it through secure patterns and a security-conscious mindset.

I recently put together a breakdown of how XSS works, including the differences between reflected, stored, and DOM-based XSS, and practical tips on how to mitigate each.

Key reminders

  • Escape output before rendering user-controlled content
  • Sanitize input, especially if you are accepting HTML or markdown
  • Use framework features as intended and avoid shortcuts like dangerouslySetInnerHTML and v-html unless absolutely necessary
  • Consider a strong Content Security Policy (CSP) as a secondary safety net

Spotting these vulnerabilities is not cause for panic. It is a sign that you are paying attention and improving the reliability and security of your application.
